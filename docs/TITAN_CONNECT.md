# Titan Connect — API клиентов клуба для сторонних сервисов

Titan Connect — собственная интеграция Titan HUB. Через неё сайт рейтинга, бот турниров, CRM или
любое другое приложение получает данные клиентов клуба: ник, имя, статус, фото, контакты, депозит,
бонусы, посещения. Клуб сам решает, что видит каждый сервис.

Подключение — **одноразовым кодом**. Сервис вводит код один раз и получает постоянный ключ. Ключ
хранится и у сервиса, и у клуба (в HUB видно, кто подключён и когда ходил). Повторно подключаться
не нужно, пока клуб не отключит сервис.

Публичная вики для разработчиков — **titanpos.ru/wiki** (`apps/web/src/app/wiki/`): подключение,
клиенты, синхронизация, ошибки и готовые клиенты на TypeScript и Python. Код примеров лежит в
`wiki/examples/snippets.ts` и проверялся против локального API.

## Как подключить (владелец клуба)

1. Titan HUB → «Управление» → «Настройки клуба» → «Интеграции» → «Titan Connect»
   (в веб-панели — «Настройки» → «Интеграции» → «Titan Connect»).
2. «Подключить сервис»: название и права (что увидит сервис) → «Получить код».
3. Код вида `K7QM-3XPA` действует 10 минут и вводится один раз. Его вводят в стороннем сервисе
   или отправляют разработчику («Поделиться кодом»).
4. Как только сервис ввёл код, экран показывает «Сервис подключён».

В карточке сервиса можно менять права (действуют со следующего запроса), выдать новый код, если
сервис потерял ключ, или отключить сервис: ключ сразу перестаёт работать.

## Права

| Право | Что даёт |
|---|---|
| `clients:read` | Всегда. Ник, имя, статус, резидент, персонал или нет, дата регистрации, ID игрока GoMafia, `deleted`. |
| `clients:photos` | `photoUrl` — фото клиента (загруженное в HUB → из Telegram → из GoMafia). |
| `clients:contacts` | `contacts`: телефон, дата рождения, Telegram. Поиск по телефону. |
| `clients:balance` | `balance`: депозит (минус — долг) и бонусные баллы. |
| `clients:visits` | `visits.count` — сколько вечеров клиент был в клубе. |

Поле, на которое нет права, в ответе отсутствует целиком.

## Для разработчика сервиса

Все ответы — JSON. Ошибки: `{ "error": { "code": "…", "message": "…" } }`.

### 1. Обмен кода на ключ

```http
POST https://<адрес клуба>/api/connect/v1/exchange
Content-Type: application/json

{ "code": "K7QM-3XPA", "service": { "name": "Рейтинг клуба", "url": "https://rating.example" } }
```

Код можно отправить на адрес клуба или на основной домен Titan: сервер сам найдёт клуб. Регистр,
пробелы и дефис в коде не важны. `service` необязателен: имя и сайт показываются владельцу в HUB.

```json
{
  "accessToken": "tcn_…",
  "tokenType": "Bearer",
  "expiresAt": null,
  "connectionId": "…",
  "name": "Рейтинг клуба",
  "scopes": ["clients:read", "clients:photos"],
  "apiBase": "https://club.titanpos.ru/api/connect/v1"
}
```

Сохраните `accessToken` и `apiBase`. Ключ бессрочный, все дальнейшие запросы идут на `apiBase`.

Ошибки обмена: `400 invalid_code` (код неверный, истёк или уже использован), `429 too_many_attempts`
(10 неверных кодов с одного IP за 15 минут).

### 2. Запросы с ключом

```http
Authorization: Bearer tcn_…
```

| Запрос | Что делает |
|---|---|
| `GET /me` | Подключение, права, клуб, `apiBase`. |
| `GET /scopes` | Справочник прав (без ключа). |
| `GET /clients` | Клиенты постранично (см. ниже). |
| `GET /clients/:id` | Один клиент. `404 not_found`, если его нет. |
| `POST /token/rotate` | Новый ключ; старый перестаёт работать сразу. |
| `DELETE /connection` | Сервис отключается сам. |

`401 invalid_token` — ключ отозван (сервис отключили или переподключили новым кодом) либо запрос
ушёл не на `apiBase`. Нужен новый код от клуба.

Лимит — 600 запросов в минуту на ключ.

### 3. Клиенты

`GET /clients` — параметры:

| Параметр | |
|---|---|
| `limit` | 1–200, по умолчанию 50. |
| `search` | Часть ника или имени. |
| `phone` | Телефон в любом виде (сравниваются последние 10 цифр). Нужно право `clients:contacts`. |
| `cursor` | Продолжение: `nextCursor` (следующая страница) или `syncCursor` (изменения с прошлого раза). |
| `updatedSince` | ISO-дата: клиенты, изменённые после неё. |
| `includeDeleted` | `true`/`false`. По умолчанию `true` при `cursor`/`updatedSince`, иначе `false`. |

```json
{
  "items": [
    {
      "id": "5b0c…",
      "nickname": "Тигр",
      "fullName": "Иван Петров",
      "status": { "key": "resident", "label": "Резидент", "color": "#8B5CF6" },
      "isResident": true,
      "isStaff": false,
      "gomafiaId": "4242",
      "registeredAt": "2026-03-01T18:00:00.000Z",
      "updatedAt": "2026-11-16T12:30:05.123456Z",
      "deleted": false,
      "photoUrl": "https://club.titanpos.ru/media/abc.jpg",
      "contacts": { "phone": "+7 900 123-45-67", "birthday": "1990-05-01", "telegram": { "id": "123", "username": "tiger" } },
      "balance": { "deposit": 1500, "bonusPoints": 120 },
      "visits": { "count": 14 }
    }
  ],
  "nextCursor": "MjAyNi0xMS0xNlQ…",
  "syncCursor": "MjAyNi0xMS0xNlQ…"
}
```

Клиенты идут по времени изменения (`updatedAt`, затем `id`). В выдачу входят и сотрудники
(`isStaff: true`): у них такой же профиль с депозитом и бонусами. Планшеты и отклонённые анкеты
не входят.

### 4. Синхронизация без повторной выгрузки

1. Первая загрузка: `GET /clients?limit=200`, затем по `nextCursor`, пока он не станет `null`.
2. Сохраните `syncCursor` из последнего ответа.
3. Дальше периодически запрашивайте `GET /clients?cursor=<syncCursor>`: придут только клиенты,
   изменённые с прошлого раза, включая удалённые (`deleted: true`). Сохраняйте новый `syncCursor`.

Изменением считается любое обновление профиля: ник, имя, фото, статус, депозит, бонусы, удаление.
Число посещений меняется вместе с чеками, а не с профилем, — его берите из `GET /clients/:id`.

## Как устроено (для команды Titan)

- Код: `apps/api/src/modules/connect/` (`public.router.ts` — API v1, `manage.router.ts` — HUB,
  `repo.ts` — подключения, `clients.ts` — выборка и сборка клиента, `codes.ts` — коды и ключи).
- Миграция `092_titan_connect.sql`: таблица `connect_connections`, колонка `profiles.updated_at`
  с триггером и индексом `(updated_at, id)`.
- В БД хранятся только sha256 кода и ключа. Код одноразовый: обмен — один `UPDATE … WHERE
  code_hash = … AND code_expires_at > now()`. Маршрут «код → клуб» лежит в общем Redis
  (`connect:code:<hash>`, 10 минут), поэтому код работает и на основном домене.
- API v1 смонтирован после гейта подписки: у заблокированного клуба данные наружу не уходят.
- Экраны: приложение HUB — `apps/mobile/src/app/(app)/manage/settings/connect/`, веб —
  `apps/web/src/app/manage/settings/ConnectSheet.tsx`.
- Проверено дымовым сценарием на локальной БД (48 проверок: обмен, одноразовость, права,
  страницы, синхронизация с удалёнными, переподключение, rotate, отзыв, перебор кодов).
